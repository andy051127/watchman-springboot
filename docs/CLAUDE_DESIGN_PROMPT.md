# 요청: "Watchman" 웹 서비스 UI 개선 디자인

## 1. 서비스 개요
Watchman은 웹캠 기반 얼굴 추적으로 공부 중 집중도를 측정하는 **학습 집중 관리 웹 서비스**입니다.
- 주 사용자: 한국어를 쓰는 학생(중·고·대학생, 수험생). 장시간 사용하고 야간에도 자주 사용합니다.
- 핵심 가치: "공부할 때 딴짓 많이 하죠?"에서 출발해 집중 시간을 측정하고, 기록과 업적으로 동기를 부여합니다.
- 기술 제약: **Vanilla HTML/CSS/JS** (프레임워크·빌드 스텝 없음). 결과물은 순수 HTML/CSS/JS로 구현 가능해야 하며, 색상·간격·폰트는 **CSS 변수(:root)** 로 정의해 주세요. 라이트/다크 모드를 모두 지원합니다.
- UI 언어: 한국어. 한글 가독성이 좋은 폰트(예: Pretendard)를 사용하고, 숫자와 타이머에는 tabular-nums를 적용해 주세요.
- 플랫폼: **웹 전용**(앱 아님). 마우스+키보드 조작과 반응형(모바일 360px ~ 데스크톱 1440px)을 모두 고려합니다.

## 2. 디자인 방향
- 키워드: 따뜻함, 차분한 집중, 절제, 신뢰감. 장식은 최소화하고 정보 위계를 분명히 합니다.
- 주황은 **Primary CTA와 핵심 강조에만** 사용합니다. 나머지는 뉴트럴 톤으로 절제합니다.
- 카드는 은은한 테두리와 약한 그림자로 구분하고, 한 화면에 Primary CTA는 1개만 둡니다.
- 모서리 반경은 8/12/16px 3단계로 통일합니다.
- 간격은 4px 배수 스케일(4/8/12/16/24/32/48)로 통일합니다.

## 3. 컬러 팔레트 (확정: Warm Ember)

|---|---|---|
| --primary | #E85D04 | #FB8A3C |
| --primary-dark (hover) | #C2410C | #F97316 |
| --primary-light (틴트 배경) | #FFF4E8 | #3A1A08 |
| --bg | #FAF8F4 | #14110F |
| --surface (카드) | #FFFFFF | #1F1B18 |
| --text | #1C1917 | #F5F1EC |
| --text-muted | #6B635C | #A8A29E |
| --border | #E8E2D9 | #2E2924 |
| --focus-ring | #2563EB | #60A5FA |
| --good | #15803D | #4ADE80 |
| --warn | #B45309 | #FBBF24 |
| --bad | #DC2626 | #F87171 |

(good/warn/bad 각각 연한 배경 토큰 --good-bg, --warn-bg, --bad-bg도 정의)

규칙:
- 주황 배경 버튼의 글자는 흰색, 16px 이상, semi-bold 이상으로 합니다. 흰 배경 위 **주황 텍스트/링크**는 대비가 부족하므로 `--primary-dark`를 사용합니다.
- 본문 텍스트 대비 4.5:1 이상, 큰 글자와 UI 컴포넌트 경계는 3:1 이상 (WCAG AA)을 지켜 주세요.
- **상태를 색에만 의존하지 않습니다.** 성공/경고/오류는 항상 아이콘+텍스트와 함께 표시합니다.
- 포커스 링은 주황이 아닌 **파란색(--focus-ring)** 으로, 브랜드 색과 시각적으로 분리합니다.

## 4. 개선해야 할 문제 (휴리스틱 평가 결과, 우선순위 순)
각 항목을 디자인에 반드시 반영하고, 반영 위치를 화면에서 확인할 수 있게 해 주세요.

### P1. 키보드 포커스 가시성 + 모달 Esc 닫기 (심각도 3 · 휴리스틱 7)
- 문제: 거의 모든 입력창이 `outline: none`에 테두리 색만 미세하게 바뀌어, 키보드 사용자가 현재 위치를 알 수 없습니다. 모달도 Esc로 닫히지 않습니다.
- 요구사항:
  - 전역 `:focus-visible { outline: 3px solid var(--focus-ring); outline-offset: 2px; }` 표준을 정의합니다. 입력창은 추가로 `box-shadow: 0 0 0 4px` 연한 파란 링을 줍니다.
  - 버튼, 링크, 탭, 체크박스, 카드형 클릭 요소 등 **모든 인터랙티브 요소**에 적용합니다.
  - 모달은 열릴 때 첫 요소로 포커스를 이동하고 Tab 포커스를 가둡니다. Esc와 바깥 클릭으로 닫히며, 닫으면 호출한 버튼으로 포커스가 돌아옵니다. 닫기(✕) 버튼과 "Esc" 힌트를 표시합니다.
  - 컴포넌트 시트에 default / hover / focus-visible / active / disabled 상태를 나란히 보여 주세요.

### P2. 플래너 CRUD 실패 시 피드백 부재 (심각도 3 · 휴리스틱 9)
- 문제: 할 일 완료 토글/삭제, D-Day 삭제가 실패해도 화면에 아무 표시가 없습니다.
- 요구사항: **공통 인라인 오류 + 토스트 시스템**을 디자인합니다.
  - 토스트 4종(성공/정보/경고/오류): 아이콘+문장+닫기, 오류 토스트에는 **"다시 시도" 버튼**을 둡니다. 화면 하단 중앙 또는 우상단에 쌓입니다.
  - 인라인 오류 배너: 폼 필드 바로 아래에 "⚠ 원인 + 해결 방법" 형태로 표시합니다.
  - 낙관적 UI 실패 시 항목이 원래 상태로 롤백되고, 해당 행이 잠깐 오류 색으로 강조되는 상태를 보여 줍니다.
  - 오류 문구는 개발 용어 없이 "무엇이 / 왜 / 어떻게" 순서로 씁니다. 예: "삭제하지 못했어요. 네트워크 연결을 확인하고 다시 시도해 주세요."

### P3. 제출 버튼 로딩 상태 (심각도 2 · 휴리스틱 1)
- 문제: 로그인/회원가입 버튼이 응답 대기 중에도 눌리고, 로딩 표시가 없습니다.
- 요구사항: 모든 제출 버튼에 **loading 상태**(스피너+"로그인 중..." 텍스트, disabled, 너비 유지)를 정의합니다. 카메라 연결 단계 표시("연결 중... → 모델 로딩 중... → 감지 준비 완료")와 같은 패턴으로 통일합니다.
- 목록형 화면(플래너, 통계, 공지사항)에는 **스켈레톤 로딩** 상태와 **빈 상태(Empty state)** 를 디자인합니다. 빈 상태에는 일러스트 대신 간단한 아이콘+한 줄 설명+CTA를 둡니다.

### P4. 할 일 삭제 보호 (심각도 2 · 휴리스틱 3·5)
- 문제: ✕ 한 번으로 즉시 영구 삭제되고, 다른 삭제 동작은 브라우저 `confirm()`을 씁니다.
- 요구사항:
  - 할 일 삭제는 **실행 취소(Undo) 토스트**("삭제했어요 · 되돌리기", 5초)로 처리합니다.
  - 그룹 탈퇴/강퇴/해산, 공지 삭제 같은 **되돌릴 수 없는 작업**은 브라우저 confirm 대신 커스텀 **확인 모달**을 씁니다. 위험 작업은 `--bad` 색 버튼으로 구분하고, 취소가 기본 포커스입니다.
  - ✕ 버튼은 hover 영역 최소 32px, 모바일 터치 영역 44px 이상으로 하고, `aria-label="할 일 삭제"` 같은 라벨을 고려한 디자인으로 합니다.

### P5. 피드백 방식 통일 (심각도 2 · 휴리스틱 4)
- 문제: 회원가입 성공은 `alert()`, 로그인 실패는 인라인, 플래너 실패는 무피드백으로 제각각입니다.
- 요구사항: `alert()`/`confirm()`을 완전히 대체하는 **하나의 피드백 규칙표**를 만들어 주세요.
  - 폼 검증 오류 → 인라인
  - 작업 성공/실패 → 토스트
  - 파괴적 작업 확인 → 확인 모달
  - 업적 달성 → 기존 achievement-toast의 별도 스타일 (같은 토스트 시스템 위에 얹습니다)
- 버튼/링크 스타일 규칙도 문서화합니다. Primary / Secondary / Ghost / Danger 4종 버튼, 텍스트 링크(밑줄+`--primary-dark`)로 구분합니다.

### P6. 폼 실시간 검증 (심각도 1 · 휴리스틱 5)
- 요구사항: 회원가입 폼에서 이메일 형식, 비밀번호 6자 이상, 비밀번호 확인 일치, 닉네임 길이를 **입력 중 실시간**으로 표시합니다(✓/✕ 아이콘+문구, 글자 수 카운터). 모든 필드에 시각적 `<label>`을 두고 placeholder를 라벨 대용으로 쓰지 않습니다. 비밀번호 표시/숨김 토글을 추가합니다. 오류가 나도 입력값은 유지합니다.

### P7. 도움말·고객센터 접근성, 캘리브레이션 안내 (심각도 2 · 휴리스틱 10)
- 로그인 후 내비게이션에 **"도움말" 메뉴**(문의하기/이용약관/개인정보처리방침/사용 방법)를 추가하거나 마이페이지와 푸터에 노출합니다.
- **캘리브레이션 화면**: 3단계 안내 스텝("① 왜 필요한가요? ② 10초 동안 평소처럼 공부하세요 ③ 완료")과 진행 바/카운트다운, "영상은 저장되지 않고 브라우저 안에서만 처리돼요" 문구를 표시합니다. 용어 옆에는 (?) 툴팁(hover와 focus 모두 동작)을 넣습니다.
- **카메라 권한 요청 직전 화면**: 왜 카메라가 필요한지, 무엇이 저장되고 무엇이 저장되지 않는지, 권한 거부 시 해결 방법을 안내합니다.

### P8. 검색/정렬/필터 (심각도 1 · 휴리스틱 7)
- 플래너 할 일 목록: 정렬(최신순/마감순/미완료 우선)과 완료 숨기기 토글, 간단한 검색창을 둡니다.
- 공지사항 목록: 검색창과 정렬을 둡니다.
- 필터가 적용되면 칩으로 표시하고, "필터 초기화" 링크와 "결과 없음" 상태를 제공합니다.

## 5. 설계할 화면 (대표 화면 우선)
1. 랜딩 (히어로+Primary CTA 1개+보조 버튼, 기능 소개 3단, 푸터)
2. 로그인/회원가입 (탭 전환, 실시간 검증, 로딩 상태, 아이디 저장)
3. 메인 대시보드 (오늘의 집중 요약, "지금 바로 시작하기" CTA, 오늘의 할 일 미리보기, D-Day)
4. 플래너 (탭: 할 일 / D-Day / 시간표, 06시~02시 시간표 그리드, 블록 추가·수정 모달)
5. 솔로 스터디 세션 (웹캠 미리보기, 타이머, 집중/딴짓 상태 배지, 세션 종료 확인 모달)
6. 그룹 스터디 룸 (참여자 타일 그리드+각자 집중 상태, 채팅 패널, 입장 시 캘리브레이션 안내)
7. 캘리브레이션 (P7 참조)
8. 통계 (일/주/월 집중률 차트, 요약 카드. 차트는 색만으로 구분하지 않고 패턴/라벨을 병행)
9. 업적 (카테고리 탭 5종, 달성/미달성/히든 카드 상태, 달성 토스트)
10. 공지사항 / 마이페이지 / 스터디 그룹 목록·상세

각 화면은 **데스크톱(1440)과 모바일(390)** 두 가지 뷰와 **라이트/다크** 모드를 모두 보여 주세요. 모바일에서는 내비게이션이 햄버거(또는 하단 탭이 아닌 상단 드로어)로 접히고, 가로 스크롤이 생기지 않아야 합니다.

## 6. 공통 컴포넌트 시트 (디자인 시스템)
다음을 한 화면에 모아 주세요. 모든 컴포넌트에 default / hover / focus-visible / active / disabled / loading / error 상태를 포함합니다.
- 버튼 4종(Primary/Secondary/Ghost/Danger)×3사이즈
- 텍스트 입력, 비밀번호 입력, 체크박스, 라디오, 셀렉트, 토글, 탭, 칩
- 토스트 4종, 인라인 배너, 확인 모달, 일반 모달
- 카드, 리스트 행(할 일/공지), 스켈레톤, 빈 상태, 툴팁
- 내비게이션 바(현재 페이지 활성 표시, 데스크톱/모바일)
- 집중 상태 배지(집중/딴짓/측정 대기), 진행 바

## 7. 접근성 및 품질 체크 (전 화면 공통)
- 키보드만으로 모든 기능에 도달할 수 있어야 하며 포커스 순서는 시각 순서와 같아야 합니다.
- 모든 아이콘 버튼에 텍스트 대체(`aria-label`)를 고려합니다.
- 최소 터치 영역 44×44px, 본문 16px 이상, 200% 확대 시에도 레이아웃이 깨지지 않아야 합니다.
- `prefers-reduced-motion` 시 애니메이션을 최소화합니다.
- 현재 위치 표시: 활성 내비게이션 링크, 긴 페이지에서는 섹션 제목/앵커를 둡니다.

## 8. 산출물 형식
1. 위 화면별 디자인 (라이트/다크, 데스크톱/모바일)
2. 공통 컴포넌트 시트
3. `:root` CSS 변수 파일(색상, 간격, 반경, 그림자, 타이포 스케일, z-index)
4. P1~P8이 각각 **어느 화면의 어느 요소에서 해결됐는지** 매핑한 체크리스트
5. 순수 HTML/CSS/JS로 옮길 수 있는 구조 (외부 UI 프레임워크 의존 없음)

불확실한 부분은 질문하지 말고, 위 제약 안에서 합리적인 기본값으로 진행한 뒤 가정한 내용을 마지막에 목록으로 알려 주세요.

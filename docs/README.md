# Watchman — 프로젝트 요약

## 프로젝트 소개

**Watchman**은 카메라와 AI 얼굴 감지 기술을 활용해 공부 집중도를 실시간으로 측정하는 웹 기반 스터디 모니터링 플랫폼입니다. 혼자 공부할 때뿐만 아니라 그룹 화상 스터디, 플래너 관리, 업적 시스템까지 제공해 학습 동기를 유지할 수 있도록 설계되었습니다.

## 주요 기능

### 집중도 측정 (핵심 기능)
- 브라우저 카메라로 얼굴을 감지해 집중/딴짓 여부를 실시간 판단
- 사용자 자세·카메라 환경에 맞게 **개인별 캘리브레이션(보정)** 기능 제공
- 집중 시간, 딴짓 시간, 집중률을 세션 단위로 기록

### 그룹 스터디룸
- WebRTC 기반 실시간 화상 스터디 (Full-Mesh P2P)
- 그룹 채팅, 집중 상태 공유 (집중 중 / 딴짓 중 표시)
- 초대코드로 그룹 참여

### 플래너
- 할 일 목록 (날짜별 Todo + 완료 체크)
- D-Day 관리
- 5분 단위 타임테이블 블록 (06:00 ~ 익일 02:00)

### 업적 시스템
- 5개 카테고리 30개 업적 (공부, 집중, 연속, 그룹, 플래너 + 히든 이스터에그)
- 세션 저장·할 일 완료·그룹 참여 등 특정 행동 시 자동 획득
- 획득 시 토스트 알림

### 공지 / 문의
- 관리자 공지사항 작성·고정
- 사용자 문의 접수 및 관리자 답변

### 관리자 페이지
- 전체 사용자 조회·삭제·관리자 권한 부여
- 문의 답변 및 삭제
- 현재 접속자 수 실시간 조회

## 시스템 아키텍처

```
[브라우저] ──HTTP/WebSocket──▶ [Spring Boot 내장 Tomcat]
                                       │
                    ┌──────────────────┼──────────────────┐
                    ▼                  ▼                  ▼
              Controller          WebSocket          Static Files
            (REST API)        (STOMP/SockJS)      (HTML/CSS/JS)
                    │
                    ▼
                Service
                    │
                    ▼
             Repository
           (JdbcTemplate)
                    │
                    ▼
                [MySQL]
```

**계층 구조:** Controller → Service (interface + impl) → Repository (interface + impl)
**인증 방식:** HTTP 세션 기반 (`userId` 세션 저장, 세션 유지 8시간)

## 기술적 도전 및 해결

### 1. 얼굴 감지 오탐 문제
책이나 태블릿을 보기 위해 잠깐 고개를 돌리는 경우에도 딴짓으로 감지되는 문제가 있었습니다. 사람마다 자세와 카메라 위치가 달라 동일한 기준을 모든 사용자에게 적용하기 어려웠습니다.

→ 사용자가 10초간 자연스럽게 움직이는 데이터를 수집해 개인별 집중/딴짓 판단 기준을 자동 설정하는 **캘리브레이션 기능**을 도입했습니다. 또한 3초 유예 시간을 두어 일시적인 고개 돌림과 실제 집중 이탈을 구분했습니다.

### 2. WebRTC 연결 순서 문제
N명이 동시에 입장할 때 ICE Candidate 메시지가 PeerConnection 설정보다 먼저 도착해 화상 연결이 끊기는 문제가 발생했습니다.

→ RemoteDescription 설정 전에 도착한 Candidate를 큐에 적재했다가, Offer/Answer 교환 완료 후 일괄 처리하는 방식으로 해결했습니다.

### 3. 업적 중복 지급 방지
여러 컨트롤러에서 동시에 업적 조건을 체크할 때 동일 업적이 중복 지급되는 문제가 있었습니다.

→ DB UNIQUE 제약 조건으로 1차 방어하고, INSERT 후 실제 저장 여부를 재조회로 검증한 뒤에만 응답에 포함하는 `tryAward()` 패턴을 적용했습니다.
